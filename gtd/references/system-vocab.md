# GTD System Vocabulary

## File map

| File | Purpose | Edited by |
|---|---|---|
| `inbox.org` | Single capture point. TODOs land here unprocessed. | Human + org-capture |
| `personal.org` | Main task system: `* Habits`, `* Active`, `* Someday`, `* Tickler`. Mixes work and personal; filter by `:work:` tag. | Human |
| `gtd.org` | Reference lists (Things to Watch, Things to Buy). Not task lists — no TODO keywords. | Human |

## Task routing

| System | What belongs there |
|---|---|
| **Sunsama** | Work-hours tasks — anything done during 9-5 on behalf of Tulip or the team: Jira tickets, work docs, ops toil, team tools. |
| **personal.org** | Personal life + career development the user owns the time and motivation for: home admin, hobby projects, personal infrastructure, career learning the user schedules themselves (e.g. CKS cert). |

Edge case test: *"who owns the time for this?"* If the user does, it stays personal even if Tulip benefits.

## Sections in personal.org

### Active (`* Active`)

Single actions and inline projects that are committed to this week. Every item has `SCHEDULED:` and `:Effort:`.

### Someday (`* Someday`)

Things to do eventually with no specific trigger date. No `SCHEDULED:` date, no `:Effort:`.

**Minimum content per item:**
- One line of **why** — so you remember what this would give you
- One line of **what the NEXT would be** — so promotion is immediate without re-deriving the first step

Weekly review question: *"Is now the right time to move this to Active?"* If yes, add `SCHEDULED:` and `:Effort:` and move it up.

### Tickler (`* Tickler`)

Things to resurface at a specific date or seasonal trigger. Has a `SCHEDULED:` date, but that date means **"review this" not "do this."**

Same minimum content as Someday (why + NEXT). At the scheduled date, decide: promote to Active, delete, or reschedule.

Good candidates: seasonal items with a natural window, conditional items with a rough future date.

If there's no trigger date at all, it belongs in Someday, not Tickler.

### Habits (`* Habits`)

Recurring practices with org-habit tracking. Each has a brief inline anchor note below the PROPERTIES block.

## Task states

| State | Meaning |
|---|---|
| `TODO` | Captured. Not yet committed to a specific day. |
| `NEXT` | Clear next physical action, ready to do. Lives only in Active. |
| `DOING` | Currently in progress (rare; for multi-day work). |
| `WAITING` | Blocked on someone else. Must have a note on who/what. |
| `DONE` | Completed. |
| `CANCELLED` | Dropped. |

`WAITING` = blocked on a **person**. If blocked on a condition or event, use `TODO` with an inline note instead.

`GROOM` is Jira integration only — do not use for personal tasks. Max 1 week before demoting to `TODO` or deleting.

## Project states (projects tracker only)

| State | Meaning |
|---|---|
| `PLAN` | Captured but not yet decomposed. |
| `ACTIVE` | Currently being worked. Has at least one `NEXT` action in Active. |
| `PAUSED` | Intentionally on hold. Should have a note on why. |
| `RETRO` | Work complete; capturing learnings before closing. |
| `COMPLETED` | Closed. Outcome achieved. |
| `ABANDONED` | Stopped pursuing. |
